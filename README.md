# micromanager

[English](README.en.md)

micromanager — экспериментальный инструмент для macOS, Windows и Linux. Вы выбираете, к каким файлам дать доступ ИИ-агенту. В терминале можно увидеть, что он хочет изменить или какую команду запустить, и одобрить либо отклонить запрос.

Инструментом можно управлять вручную, подключить локальную модель в Ollama или облачную через OpenAI-совместимый API. Для внешних клиентов он работает как сервер MCP (Model Context Protocol).

За соединение между компьютерами по ключу, в том числе через NAT, отвечает iroh. Терминальный интерфейс написан на ratatui.

## Установка (одна команда)

[Скачать micromanager v0.0.4](https://github.com/metalebedenko/micromanager/releases/tag/v0.0.4). Готовые сборки доступны для macOS на Apple silicon (arm64) и Intel (x86_64), Windows x86_64 и Linux x86_64. Rust для установки готового приложения не требуется.

В v0.0.4 обновлены зависимости и усилена защита журналов, ключей и настроек. Установщик сверяет SHA-256 архива до распаковки.

**macOS / Linux:**
```bash
curl -fsSL https://raw.githubusercontent.com/metalebedenko/micromanager/main/install.sh | sh
```

**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/metalebedenko/micromanager/main/install.ps1 | iex
```

Скрипт выбирает сборку для вашей системы из последнего [релиза](https://github.com/metalebedenko/micromanager/releases/latest) и проверяет контрольную сумму архива. В macOS и Linux программа устанавливается в `~/.local/bin`, в Windows — в `%LOCALAPPDATA%\micromanager\bin`.

**Из исходников** (любая платформа, нужен [Rust](https://rustup.rs)):
```bash
cargo install --git https://github.com/metalebedenko/micromanager
```

## Команды

```bash
micromanager tui                      # чат, список действий, подтверждение запросов и настройки
micromanager serve                    # запустить MCP-сервер со связью через stdio
micromanager agent "<задача>"         # передать задачу локальной модели в Ollama
micromanager listen [--allow-path …]  # создать приглашение для удалённого подключения
micromanager connect <код>            # подключиться к компьютеру по приглашению
micromanager telegram [--nl]          # управление своим компьютером из Telegram
```

В TUI: `g` — подключиться к удалённой машине по коду, `p` — поделиться своей машиной, `s` — настройки, `?` — справка.

## Удалённое управление

Для разового подключения владелец запускает `listen` или нажимает `p` в терминальном интерфейсе и передаёт код приглашения. На втором компьютере код вводят через `connect` или клавишу `g`. iroh устанавливает защищённое соединение и проверяет ключ узла. На компьютере владельца продолжают действовать подтверждения, ограничения на доступные пути, срок разрешения и запреты на опасные команды.

По умолчанию для следующего подключения нужен новый код. В режиме `listen --remember` программа сохраняет ключ узла и список доверенных компьютеров. Для повторного подключения служит `connect --resume`, для отзыва доступа — `forget`.

## Безопасность

Перед записью журнала и отправкой автоматического отчёта маскируются известные форматы ключей и паролей. Запрос с распознанными учётными данными отклоняется в режиме подтверждения через Telegram. Для такого действия нужен локальный режим. Конфигурация и ключи записываются атомарно, а журнал на Unix доступен владельцу файла. Произвольный текст всё равно может содержать личные сведения. Для публичного обращения используйте короткое обезличенное описание проблемы.

Каждое действие проходит многослойный гейт **до** исполнения:

1. **Anti-bypass-парсер** — разворачивает обёртки-интерпретаторы (`sudo`, `env`, `eval`, `bash -c`, …), бьёт цепочки (`&&`, `|`, `;`, перевод строки), снимает кавычки/escape и извлекает подстановки. Нераспарсиваемое → `Deny` (fail-closed).
2. **Hardline-blocklist** — неперебиваемый список катастрофичных операций (`rm -rf` системных путей, `mkfs`, `dd` на устройство, `format`, `diskpart`, …), *nix и Windows одновременно. Работает по всем сегментам и обёрткам.
3. **Risk-тиры + confirm-гейт** — мутации и команды требуют подтверждения владельца; только read-операции авто-разрешаются.
4. **Path-scope + secret-scoping** — грант ограничивает доступные пути; секрет-подобные файлы (`*.env`, `*.key`, `*secret*`) не отдаются даже на чтение.
5. **Fail-closed audit-log** — каждое решение и результат пишутся в журнал; недоступность журнала для мутации → отказ.

Ключ iroh можно зашифровать парольной фразой из `MM_KEY_PASSPHRASE` (Argon2id и ChaCha20-Poly1305). В Unix у файлов состояния права `0600`. Если записать API-ключ модели в конфигурацию, он останется там в открытом виде. Для облачной модели предпочтительнее передать ключ через переменную окружения.
