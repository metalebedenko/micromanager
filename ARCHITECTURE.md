# Архитектура

micromanager — один статичный бинарь на Rust. Ядро — MCP-сервер «руки», вокруг которого
построены фронты (TUI, CLI, Telegram) и транспорты (in-process, P2P по iroh).

## Принцип

«Руки» (исполнительная поверхность) и «мозг» (интеллект) разделены. Руки — это MCP-сервер
с фиксированным набором безопасных инструментов. Мозг — любой MCP-клиент: локальная LLM,
облачная модель, внешний агент или человек через TUI. Один и тот же путь исполнения работает
и локально (в том же процессе), и удалённо (между машинами) — меняется только транспорт.

## Слои

```
                фронты:  TUI (ratatui) · CLI · Telegram
                            │
                       «мозг»-клиент (Ollama / OpenAI-совм. / внешний MCP / человек)
                            │  MCP (rmcp)
        ┌───────────────────┴───────────────────┐
        │            HandsServer («руки»)        │
        │   5 инструментов: list_dir · read_file │
        │   · search · write_file · run_shell    │
        └───────────────────┬───────────────────┘
                            │  каждый вызов
                  ┌──────────┴──────────┐
                  │     Safety-гейт     │  parser → blocklist → risk → confirm → scope
                  └──────────┬──────────┘
                            │
                  ┌──────────┴──────────┐
                  │   Audit (fail-closed)│
                  └─────────────────────┘
```

## Компоненты (`src/`)

| Модуль | Назначение |
|---|---|
| `server/` | `HandsServer` (rmcp) + 5 инструментов; обёртки над чистой логикой (`*_impl`). |
| `safety/` | Гейт: `parser` (anti-bypass), `blocklist` (hardline), `risk` (тиры), `policy` (scope/паттерны), `mod` (`gate`/`authorize`). |
| `audit/` | JSON-lines журнал решений и результатов; fail-closed для мутаций. |
| `brain/` | Трейт `Brain` (сменный мозг) + `OllamaBrain`, `OpenAiBrain`, `RoutingBrain` (fallback). Агент-цикл `run_agent_with` через трейт `ToolRunner`. |
| `net/` | iroh-транспорт, pairing/auth (`Gatekeeper`), удалённые и in-process MCP-сессии, persistence спаренных узлов. |
| `tui/` | Чистый `App`-редьюсер (состояние и переходы — юнит-тестируемо) + тонкий ratatui-цикл + канальные швы `Confirmer`/`Audit`. |
| `tg/` | Telegram-фронт: команды/NL → safety+audit → ответ; inline-кнопки подтверждения; отчёты владельцу. |
| `command.rs` | Единый парсер команд для TUI и Telegram. |
| `paths.rs` | Платформенная папка состояния (per-user). |

## Поток исполнения

1. Клиент (мозг) вызывает MCP-инструмент с аргументами.
2. `HandsServer` строит `Action` и зовёт `gate(...)`:
   `run_shell` дополнительно проходит anti-bypass-парсер (развёртка обёрток, сплит цепочек),
   затем hardline-blocklist по сырой команде и по каждому сегменту.
3. Вердикт: `Allow` (только low-risk read) · `Ask` (подтверждение владельца) ·
   `ConfirmDangerous` (громкое подтверждение при owner-override) · `Deny`.
4. `authorize` применяет вердикт через инъектированный `Confirmer` (stdin / TUI-канал /
   Telegram-кнопки / вето владельца B).
5. Результат и вердикт пишутся в `Audit` (fail-closed: нет журнала для мутации → отказ).

## Транспорт

- **Локально:** мозг и руки соединены через `tokio::io::duplex` — настоящий MCP без сети.
- **Между машинами:** iroh даёт прямое P2P-соединение по публичному ключу (dial-by-key),
  identity пира криптографически верифицируется на уровне транспорта. Поверх — тот же MCP.
- **Pairing:** одноразовый секрет (142 бита) в коде-приглашении + allowlist по `EndpointId`.
  Секрет «сгорает» атомарно (одноразовость под гонкой), сравнивается constant-time,
  имеет TTL и лимит попыток. Опц. постоянный доступ — стабильная личность + персист allowlist.

## Модель безопасности

- **Fail-closed везде:** нераспарсиваемое, неизвестное, недоступный журнал → отказ.
- **Hardline неперебиваем:** срабатывает до approval-слоя, ловится через обёртки и цепочки;
  регрессия покрыта табличным тестом опасных команд (`tests/safety_bypass.rs`).
- **Вето у владельца машины:** мутации требуют явного подтверждения; при удалённом доступе
  второго подтверждения на стороне A нет — решает только владелец B.
- **Грант сужает, не расширяет:** `allowed_paths` + `allow_shell` + TTL; секрет-scoping
  блокирует чтение чувствительных файлов.
- **Кросс-платформа first-class:** детекторы *nix и Windows активны всегда (управляемая
  машина может быть любой ОС).

## Тесты

Юнит-тесты чистой логики (редьюсеры, парсеры, политики) + интеграционные (MCP loopback,
pairing, удалённые сессии) + регресс-таблица safety-байпаса. Кросс-платформенная CI-матрица.
